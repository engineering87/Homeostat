# Design decisions

This page records the decisions behind Homeostat's behavior that were taken on purpose, often after a review found a
failure, and that a later change could undo without noticing. It is for contributors and reviewers: before changing
something listed here, read why it is so, and update this page and its guarding test in the same pull request if the
decision changes.

Each entry gives the decision, the reason, what not to do instead, and the tests that guard it. A review finding that
contradicts an entry is not a bug by itself: it needs a new argument that the reason no longer holds.

## Failure isolation

| ID | Decision | Reason | Do not | Guarded by |
|---|---|---|---|---|
| F1 | Every wait on the store, a coordinator, an action, a verifier, a detector or a consumer is bounded, and runs off the caller's thread (`Task.Run` before awaiting). | A store or client may block synchronously before returning its task; the caller (startup, a request, the health check, the engine loop) must never wait for it. | Await a store call directly on a request or engine thread; rely on the callee honoring its token. | `ReliabilityTests.A_store_that_never_answers_does_not_block_startup_health_checks_or_shutdown`, `FailureIsolationTests.The_health_check_answers_in_time_when_the_store_blocks_its_caller`, `CoreReviewTests.Startup_does_not_wait_for_the_saved_baselines`, `ControlReviewTests.Listing_pending_approvals_does_not_block_the_caller_when_the_store_blocks` |
| F2 | A call abandoned at its timeout is not started again until it ends (actions, compensations, verifiers, detectors, consumers, health check reads, periodic refresh, plan state reads and cluster lease requests before a run, condition history reads and writes, seasonal baseline loads and saves). While it runs, the caller fails closed at once (a plan does not start, the history shows this instance's events) or waits for the same call again (a history write). Reads made for a request (status, pending approvals) are bounded (F1) but not de-duplicated. | Restarting a call that ignores cancellation piles up blocked threads until the thread pool starves; a triggering signal or a periodic task can come many times a second. | Start a fresh call on every tick, signal or retry of a background task. | `FailureIsolationTests.An_action_whose_previous_call_is_still_running_is_not_started_again`, `ReliabilityGapTests.A_verifier_that_never_returns_is_not_started_again_while_it_runs`, `ReliabilityGapTests.A_detector_that_hangs_is_not_called_again_until_it_returns`, `CoreReviewTests.A_plan_state_read_that_never_answers_is_not_started_again_by_each_signal`, `CoreReviewTests.A_history_read_that_never_answers_is_not_started_again_by_each_request`, `CoreReviewTests.A_history_write_that_never_answers_is_waited_for_again_instead_of_started_again`, `CoreReviewTests.A_periodic_baseline_save_that_never_answers_does_not_hold_the_shutdown_and_is_not_started_again` |
| F3 | The services of a step (its DI scope) are disposed only when an abandoned action or verifier has really ended; a service that fails to dispose is logged and does not change the step's outcome. | Disposing under a running call makes it fail in unrelated ways (ObjectDisposedException in the user's code); the outcome is already decided when the scope ends. | Dispose the scope at the timeout; let a disposal exception turn a healed run into a failed one. | `ReliabilityTests.An_action_that_ignores_cancellation_does_not_hold_the_concurrency_slot`, `CoreReviewTests.A_step_service_that_fails_to_dispose_does_not_turn_a_healed_run_into_a_failed_one` |
| F4 | No exception leaves a background service, a timer callback or an event handler; a fatal engine error turns off the switches its conditions turned on. | An exception out of a `BackgroundService` stops the host by default (`StopHost`); a crashed engine must not leave the application degraded. | Let a background loop throw; leave switches on after the engine stopped. | `ReliabilityTests.A_failure_classifier_that_throws_never_fails_the_application_call`, `PollyControlTests.Switch_changes_raise_events_only_on_change_and_survive_failing_handlers` |
| F5 | Configuration that is invalid is logged as critical and skipped (`failOnInvalid: false` by default); option values that would break timers are refused at startup (`DetectionInterval` >= 1 ms, every timer value <= about 49 days). | A typo in a reloaded configuration must not stop the application; a timer that throws would. | Throw on invalid configuration by default; accept values that `PeriodicTimer` or `Task.Delay` refuse. | `FailureIsolationTests.An_invalid_condition_in_configuration_does_not_stop_the_application` |
| F6 | The file store opens lazily and retries every 10 seconds; the Redis connection is resolved on first use and, after a failure, again at most every 10 seconds (store and coordinator). Until the control state is read, Homeostat counts as paused. | A locked file or a Redis server down at startup must not stop the application, and Homeostat must not act before it knows whether a person paused it. With `AbortOnConnectFail=true`, resolving blocks a thread for the connect timeout: once per store call would starve the thread pool. | Open the store in the constructor; act with an unknown control state; resolve a failed connection again on every call. | `FailureIsolationTests.A_store_file_locked_by_another_process_does_not_stop_the_application`, `ReliabilityGapTests.A_store_file_locked_at_startup_is_opened_once_the_lock_is_released`, `SharedControlTests.Homeostat_counts_as_paused_until_the_control_state_is_read`, `ControlReviewTests.A_failed_Redis_connection_is_not_resolved_again_on_every_call` |
| F7 | Memory is bounded whatever the load: windows keep about 8,192 points, occurrence counts the latest `count` matches, metric series 10,000 per instrument, alert series 1,000 per source and 10,000 in all, latency samples per interval. | A self-healing library must not become the memory leak it is meant to heal. | Add a per-signal or per-tag collection without a cap and a documented limit. | `ResourceBoundsTests.*`, `DocumentationTests` (limits stated in the docs), `CoreReviewTests.Occurrences_keep_only_as_many_matches_as_the_count` |
| F8 | Detectors run concurrently, each call waited for on its own (bounded as in F1). | One slow detector (up to 30 seconds per call) would delay every other signal. | Await detectors one after another, or all together before the next interval. | `CoreReviewTests.A_slow_detector_does_not_delay_the_others` |
| F9 | A Redis lease acquisition that fails (a client-side timeout) is released with its own token before the error is passed on (best effort, 2 seconds at most). | Redis may have applied `SET NX` although the reply was lost: the lease would have no owner until it expires, and the plan could run nowhere meanwhile. | Rethrow without releasing; release without the token. | `ControlReviewTests.A_lease_whose_acquisition_timed_out_after_Redis_applied_it_is_released` |

## Shared control (pause, switches, approvals)

| ID | Decision | Reason | Do not | Guarded by |
|---|---|---|---|---|
| S1 | Changes that make Homeostat do less (pause, switch off, release) apply on the instance at once and are written when the store answers; changes that let it act (resume, switch on) fail (`503`) when the store is unavailable. | Fail safe: an outage must never stop a person from stopping Homeostat, and must never let it act on a decision the cluster did not record. | Make safe changes wait for the store; apply unsafe ones locally. | `FailureIsolationTests.With_the_store_down_turning_off_and_pausing_take_effect_at_once_and_are_written_when_it_recovers`, `AspNetCoreTests.Changes_that_would_let_Homeostat_act_answer_503_when_the_store_is_unavailable_and_safe_ones_apply_here` |
| S2 | Pause and switch writes carry the time of their decision, by the deciding instance's clock (clocks must be synchronized, documented); the store refuses a write older than the latest decision about the same pause or switch. On a tie, the decision that makes Homeostat do less wins. A change in the safe direction that the store refuses is logged as a warning naming the later decision the store holds (debug only when the store already shows the safe state). | A write that timed out on its instance can reach the store later and would otherwise undo a newer decision. A person whose pause or turn-off loses to a later decision (or to a clock ahead) must be told. | Last-writer-wins by arrival; unordered `Set...` methods; store the store's own time instead (a redesign); treat a refused safe change as silently written. | `DistributedTests.Pause_and_switch_writes_apply_in_decision_order` (memory, file, Redis), `ControlReviewTests.A_pause_refused_for_a_later_resume_is_logged_as_a_warning_naming_it`, `ControlReviewTests.A_deferred_pause_refused_for_a_later_resume_is_logged_as_a_warning`, `ControlReviewTests.A_deferred_turn_off_superseded_by_a_later_turn_on_is_logged_as_a_warning` |
| S3 | A renewal of a cluster plan's claim is not a decision: it keeps the claim's decision time and records `RenewedAt`; a release decided before the renewal is refused. The owner's own release applies at once and is stamped after any renewal of its own still on its way to the store, so it is never older than its own renewal. | A person's turn-off decided after the claim must apply even if the owner renewed meanwhile, and a stale release must not turn off a switch its owner still holds. | Record the renewal as the latest decision; accept a release older than the renewal; wait for the owner's renewal before releasing (it would hold the release while the store hangs, against S1); stamp the owner's release before its in-flight renewal. | `DistributedTests.Pause_and_switch_writes_apply_in_decision_order` (renewal cases), `ControlReviewTests.The_owners_release_is_not_refused_by_its_own_renewal` |
| S4 | A resume or a turn-on that times out is decided again in the safe direction (pause again, turn off). A pause made while a resume is being written stands. | The store may run the timed-out write later; the caller was told it failed, so the safe state must win. | Leave the outcome of a timed-out unsafe write to chance. | `FailureIsolationTests.A_pause_made_while_a_resume_is_being_written_stands` |
| S5 | Pending safe changes survive failed refreshes and refused claims, and are written even while the state cannot be read, one write at a time per change. | A deferred release or switch-off that is dropped leaves the application degraded with nobody owning the switch. | Clear deferred changes on a failed read. | `FailureIsolationTests.A_release_deferred_during_an_outage_survives_the_failed_refreshes`, `FailureIsolationTests.A_refused_claim_does_not_drop_a_pending_switch_off` |
| S6 | A switch a person turned on is never taken over or turned off by a plan; a plan's switch owned by an instance that is gone is released by another instance once the condition is not active there, as of the renewal it saw. "Gone" means not renewed for 4 renewal periods (at least 1 minute) of the observer or of the owner (`SwitchState.RenewInterval`, recorded in the claim), whichever is longer, plus 30 seconds for clock differences when the claim records the owner's period; a claim without it uses the observer's period alone, as before. | People decide over automation; orphaned switches must not stay on; an owner configured to renew less often must not lose a live claim. | Let a plan claim a person's switch; release an orphan renewed since it was seen; judge another instance's claim by the observer's period alone. | `SharedControlTests.A_plan_never_takes_over_an_application_switch_turned_on_by_a_person`, `FailureIsolationTests.A_switch_turned_on_by_an_instance_that_is_gone_is_turned_off_by_another`, `FailureIsolationTests.A_switch_claimed_after_its_step_timed_out_is_released`, `ControlReviewTests.An_owner_that_renews_less_often_keeps_its_switch` |
| S7 | `HoldAtMost` turns a switch off after its limit even if the condition never clears, and only ends the claim it was set for. | An action can keep its own condition active (a paused consumer grows its own backlog). | Rely only on the condition clearing. | `FailureIsolationTests.HoldAtMost_turns_the_switch_off_even_if_the_condition_never_clears` |
| S8 | A pause that cannot be read counts as a pause until a person resumes: an unreadable Redis pause record is reported as an indefinite pause; an unreadable store file is set aside and the file store starts paused (written before the file is moved). Both are logged as critical. | The record may have held a person's pause: reading it as "not paused" would let Homeostat act through it. | Skip an unreadable pause like other records; start the file store empty and unpaused. | `ControlReviewTests.An_unreadable_Redis_pause_record_counts_as_a_pause`, `ControlReviewTests.An_unreadable_store_file_starts_the_store_paused` |
| S9 | Once the store took a resume or a turn-on, a change in the safe direction about the same thing decided at or after it stays shown on the instance, even once written; an older one is replaced. | A pause decided after a resume, written while the resume's write returned, must not be hidden until the next read. | Let a written change of either direction be replaced by an older one. | `ControlReviewTests.A_pause_written_while_an_older_resume_returns_stays_shown`, `FailureIsolationTests.A_pause_made_while_a_resume_is_being_written_stands` |
| S10 | A cluster plan's turn-on step fails (`InvalidOperationException`) when the store refused its claim and the switch is off there (turned off after the step started); it succeeds when the switch is on for a person or another condition. | A step must not report success for a switch that is not on. | Treat every refused claim as success. | `ControlReviewTests.A_turn_on_step_whose_claim_is_refused_with_the_switch_off_fails`, `FailureIsolationTests.A_refused_claim_does_not_drop_a_pending_switch_off` |
| S11 | Approvals: an answer whose write times out is read back once: `true` if the store recorded it, `false` if it recorded another answer, otherwise a `TimeoutException` saying the outcome is unknown. A request whose registration timed out is removed once its late write ends (bounded, in the background). Every store also drops requests a day after they expired. | The store may apply a timed-out write later: the caller must not be told an approval failed that then runs the step, and nobody must find a request nobody waits for. | Report a timed-out answer as failed; leave late requests listed. | `ControlReviewTests.An_answer_that_timed_out_but_was_recorded_succeeds`, `ControlReviewTests.An_answer_that_timed_out_and_is_still_pending_reports_an_unknown_outcome`, `ControlReviewTests.A_request_written_after_its_registration_timed_out_is_removed`, `ControlReviewTests.The_memory_store_drops_requests_a_day_after_they_expired` |

## Healing behavior

| ID | Decision | Reason | Do not | Guarded by |
|---|---|---|---|---|
| H1 | Dry-run is on by default; the budget, cooldowns, maintenance windows and approvals apply before every step. | Nothing acts until someone has seen what it would do. | Default to acting. | `EngineTests`, `ActionBudgetTests` |
| H2 | A compensating action (`UndoWith`) is never blocked by the pause, maintenance windows or the budget; it runs after a step that timed out or did not heal, not after an action that refused. After an action abandoned at its timeout, it runs once the action has ended, waiting at most the action timeout; if the action still runs then, it is not run (`UndoSucceeded = false`, an error asks for a person). | Undoing is always the safe direction, and a timed-out action may have half-applied; an undo that runs while the action still runs can be overwritten by it. | Gate compensations like actions; run the undo concurrently with the abandoned action; wait for it without a bound. | `SharedControlTests.A_compensating_action_still_runs_when_Homeostat_was_paused_meanwhile`, `DistributedTests.A_step_that_does_not_heal_is_compensated_before_escalating`, `CoreReviewTests.The_compensation_of_an_abandoned_action_runs_once_the_action_has_ended`, `CoreReviewTests.The_compensation_of_an_action_that_never_ends_is_not_run_and_the_run_ends` |
| H3 | The default verifier reports `Healed` as soon as the condition is no longer `Active` (`Pending` included). | `Pending` after an action means the episode cleared and a new one started counting. | Treat `Pending` as not healed. | `ReliabilityGapTests.A_condition_that_cleared_and_counts_again_is_healed_for_the_verifier` |
| H4 | A signal without a value neither triggers nor clears value, trend, anomaly, projection or seasonal rules. | A probe that could not measure says nothing about the value. | Clear a value rule on a healthy signal without a value. | `AdvancedConditionTests.Value_thresholds_are_not_cleared_by_a_signal_without_a_value`, `AdvancedConditionTests.Trend_rules_ignore_signals_without_a_value` |
| H5 | Restart limits are counted per fixed window aligned on UTC: attempts of the current window plus restarts allowed in the previous one; no counter is ever reset; refused attempts count only against their own window. Each counter records as its end (`LastRunEndedAt`) the moment it stops being read, so the store's retention removes it later. | A reset racing with a count let one restart too many; counting refused attempts across windows blocked restarts forever; counters without an end were kept forever, one per window. | Sliding windows with resets; counting refusals in the next window; counters without an end. | `ReliabilityGapTests.Restart_limits_hold_when_every_replica_restarts_at_the_same_moment`, `ReliabilityGapTests.Refused_restarts_do_not_block_the_windows_after_them`, `CoreReviewTests.Restart_counters_carry_an_end_so_the_store_retention_removes_them` |
| H6 | `RestartHostedService` stops with a bounded wait, starts again even if stopping failed or timed out, and never starts while the application is stopping. | A service whose stop hangs would otherwise stay down; starting during shutdown fights the host. | Wait for an unbounded stop; restart during shutdown. | `ReliabilityGapTests.A_hosted_service_whose_stop_hangs_is_started_again`, `ReliabilityGapTests.A_hosted_service_is_not_started_again_while_the_application_stops` |
| H7 | `ChaosEnabledBySwitch` stops chaos after a maximum duration (1 hour by default); turning the switch off, even with no call in between, starts a new round. | A game day nobody ended must not keep degrading the application. | Chaos with no end; a clock reset only by calls. | `PollyControlTests.Chaos_stops_by_itself_after_its_maximum_duration` |
| H8 | On the system clock, a signal timestamped more than 1 minute ahead of the instance's clock is processed as of now (with a rate-limited warning); past timestamps are kept; with a simulated clock (`HomeostatTestHost`, replays) timestamps are kept as given. | One timestamp from a clock that runs ahead would hold trend and anomaly windows, occurrence counts and suppression freshness for as long as its skew; tests feed signals ahead of the simulated clock on purpose. | Trust future timestamps; clamp timestamps in the past; clamp under a simulated clock. | `CoreReviewTests.A_signal_from_a_clock_ahead_is_processed_as_of_now_and_past_ones_are_kept`, `HistoryAndSeasonalityTests.Seasonal_baselines_survive_a_restart` |
| H9 | A verifier is resolved inside the guard that turns its failures into `Inconclusive`. | A verifier whose constructor throws must not fail the run and lose the step's result. | Resolve it before the guard. | `CoreReviewTests.A_verifier_whose_constructor_throws_makes_the_step_inconclusive_and_keeps_its_result` |

## Integrations

| ID | Decision | Reason | Do not | Guarded by |
|---|---|---|---|---|
| I1 | The Slack endpoint waits at most 2 seconds for the store, answers Slack at once and updates the message in the background; Slack replies go only to `hooks.slack.com` and `hooks.slack-gov.com`. | Slack needs an answer within 3 seconds; a forged payload must not make the application call arbitrary URLs. | Await the reply post on the request. | `SlackInteractionTests.*` |
| I2 | Control endpoints refuse to map without an authorization policy or an explicit opt-out, and require a bearer token or `X-Requested-With`, refusing cross-site requests. | They pause healing and turn switches: they need authentication and CSRF protection. | Map control endpoints anonymously by default. | `AspNetCoreTests.Endpoints_refuse_to_map_without_a_policy_or_an_explicit_opt_out`, `AspNetCoreTests.Endpoints_require_the_given_policy` |
| I3 | Options that could never produce a meaningful signal are refused at registration (HTTP and call signal ratios in (0, 1] and ordered, NaN refused, positive latencies, `MinimumCalls` >= 1; `RatioOf` with another statistic; metric, event counter and probe thresholds finite and ordered). | Silent misconfiguration produces conditions that never trigger. | Accept and ignore. | `HttpSignalTests.Signal_settings_that_could_never_work_are_refused`, `MetricSignalTests.Metric_signals_need_a_threshold_and_a_ratio_rule`, `CoreReviewTests.Metric_signal_thresholds_must_be_finite_and_ordered`, `FacilitatorTests` |
| I4 | Event counter and metric thresholds are inclusive (at or above, the `Thresholds` helper); probe, Kafka and memory cache thresholds are strict, as documented per detector. | Each follows its documented contract; changing one silently shifts when conditions trigger. | Unify by changing behavior without changing the docs and a major version. | `DetectorTests`, `MetricSignalTests` |
| I5 | Kafka's pause gate never resumes partitions the application paused itself; Service Bus resumes only a processor Homeostat stopped. A Service Bus pause that finds the processor not started stands: while it stands, the processor is watched (about every second, never throwing, until the resume or the processor closes) and stopped as soon as it starts processing, and then counts as stopped by Homeostat. | Homeostat must not undo the application's own backpressure; a switch already on at startup must not let the processor the application starts afterwards run while paused. | Resume the whole assignment or any stopped processor; treat a pause of a processor not yet started as done. | `MessagingTests.Kafka_resume_leaves_the_partitions_the_application_paused`, `IntegrationReviewTests.A_Service_Bus_processor_paused_before_it_starts_is_stopped_when_it_starts_and_resumed_after`, `IntegrationReviewTests.A_Service_Bus_processor_the_application_never_started_is_not_started_by_the_resume` |
| I6 | The Homeostat health check reports a store it cannot read as Degraded, whatever `attentionStatus`. | The store is shared: an outage fails the check on every replica at once, and Unhealthy would take them all out of rotation for a problem of Homeostat, not of the application. | Report a store outage with the attention status. | `IntegrationReviewTests.A_store_outage_is_reported_as_degraded_even_with_an_unhealthy_attention_status` |
| I7 | Control endpoints, Slack and Teams tell a store timeout from a store failure ("nothing was changed", `503`): a timed-out approval or hold release "may still be applied; check before retrying"; a timed-out resume or turn-on "was not made" (it is decided again in the safe direction, S4); Teams keeps a timed-out message marked as handled. Store calls run without the request's token (only the wait ends with the request); a disconnected client gets no answer and no unhandled error. `GET /status` reports the type of a store error, never its message. | A timed-out write may still land: saying nothing changed invites a second, conflicting change; a disconnect must not cut a change short halfway; store messages can name servers. | Report every store exception as "nothing changed"; pass the request token to the store; return exception messages. | `IntegrationReviewTests.A_store_timeout_answers_that_the_change_may_still_apply_and_a_failure_that_nothing_changed`, `IntegrationReviewTests.Teams_keeps_a_timed_out_message_as_handled_and_lets_a_failed_one_be_sent_again`, `IntegrationReviewTests.A_client_that_disconnects_does_not_cut_a_change_short_nor_raise_an_unhandled_error`, `IntegrationReviewTests.Status_reports_the_store_error_without_its_message` |
| I8 | Names in control routes decode `%2F` only (ASP.NET Core leaves it escaped and decodes every other escape); release names are validated like switch names (at most 200 characters, no control characters). | The dashboard and the CLI escape a slash as `%2F`; decoding the whole value again would change names that contain `%`. | `Uri.UnescapeDataString` on route values (a double decode). | `IntegrationReviewTests.Names_with_a_slash_reach_the_switch_and_condition_they_name` |
| I9 | `DisableFrontDoorOrigin` checks the group before the change and reads it again after: if no other origin is enabled any more, it enables this origin again and fails. | Check-then-act: two plans could otherwise take the last two origins out of rotation; when both restore, traffic keeps flowing. | Rely on the check before the change alone. | `IntegrationReviewTests.A_Front_Door_origin_is_enabled_again_when_the_other_origins_were_disabled_meanwhile` |
| I10 | Steps that act on shared resources (`RolloutRestart`, `ScaleDeployment`, every Azure step) are documented as needing `OncePerCluster()`; there is no run-time warning. | With the default scope a condition active on N replicas runs them N times. A warning would need the plan's scope, which the integration packages cannot see (it is internal to the core, and `OncePerCluster()` can be called after the step). | Remove the documentation; add a warning that guesses the scope. | Review (docs/cloud.md, XML documentation) |
| I11 | A circuit breaker source keeps every provider tracked for it and publishes the worst state; providers are held strongly, dropped when their pipeline is disposed (`ObjectDisposedException`), at most 32 per source (oldest dropped). A pipeline rebuilt by hand without disposing the old one keeps the old breaker's last state in the source: give each pipeline instance its own source, or dispose the old pipeline. | Several pipelines can share a source; a provider references its breaker but nothing in the pipeline references the provider, so a weak reference would drop live pipelines. | Keep only the last provider; hold providers weakly. | `IntegrationReviewTests.A_circuit_breaker_source_reports_the_worst_state_of_its_pipelines_and_drops_disposed_ones` |
| I12 | The `Homeostat.Switch` feature filter warns about invalid parameters once per feature, for at most 1,000 features. | Each feature can have its own mistake; the set must stay bounded. | Warn once per filter; remember every name. | `IntegrationReviewTests.Invalid_switch_filter_parameters_are_warned_about_once_per_feature` |

## Packaging and repository

| ID | Decision | Reason | Do not | Guarded by |
|---|---|---|---|---|
| P1 | One package per third-party dependency; packages without a dependency of their own live in the core (`Homeostat.Data` was merged). | Users install only the dependencies they use; fewer packages to keep stable. | Merge packages with different third-party dependencies; split the core without a dependency reason. | `PublicApiTests` |
| P2 | Stability levels: `HomeostatPreview` packages are numbered `X-preview.1` on a release and `X-preview.0.<suffix>` on a prerelease; the release version comes from `-p:HomeostatVersion`. | Limit the 1.0 promise to what has been proven; the prerelease numbering sorts below the release, so users of a candidate get the release as an update. | Pass `-p:Version` in the release workflow (it would override the suffix); give preview packages the `rc` label (it sorts above `preview`, so the candidate would stay the latest version). | `DocumentationTests.The_documented_stability_of_each_package_is_the_one_it_is_built_with` |

| P4 | `.gitignore` rules for sample output are anchored (`/data/`, `/samples/*/data/`). | Git ignores case on Windows and macOS: a bare `data/` hid `src/Homeostat/Data/`. | Add unanchored rules named like source folders. | CI build (the sources would be missing) |
| P5 | Commit messages follow Conventional Commits with the scopes in `commitlint.config.mjs`. | CI rejects other scopes. | Invent scopes (`build`, `core-engine`). | `commitlint` workflow |
| P6 | Examples use neutral domains (weather feed, forecast, geocoder, reports database, telemetry, document ingestion). | Consistency and no overlap with other publications. | Introduce e-commerce or workplace-specific examples. | Review |
| P7 | `Homeostat.Testing` depends on exactly the Homeostat version it was built with (`[x]`), set by a target after `_GetProjectReferenceVersions`. | It uses Homeostat internals (signal replay): a newer Homeostat would break it at run time. | Leave the default `>= x` dependency. | Pack and read the nuspec (`docs/testing.md`) |
| P8 | Tests that drive shared control by hand either freeze the simulated clock (`AutoAdvanceStep = null`) or refresh twice, and wait for events and store writes instead of asserting right after one call. | Moving a test host's clock also wakes its periodic refresh, which runs concurrently: a refresh joins a read already in flight (possibly older than the test's change), and the periodic sweep can take a write the test's own call then finds running. ## Kept as they are after review

Findings that were examined and deliberately not acted on, so they are not raised again without a new argument:

- OpenFeature resolutions report `Reason.Static`: a switch does not depend on the evaluation context, and changes
  reach providers through `ProviderConfigurationChanged` events.
- Larger refactorings (one shared read helper for the broker packages, moving the HTTP handler onto `CallRecorder`)
  were postponed: they change no behavior and touch tested hot paths.
- Decision records of switch names are not pruned (one small record per distinct name, in memory and in the Redis
  `decided` hash): names come from plans and from the authorized control endpoints, and a record must outlive any
  late write about its switch (decision S2).
- Switch change events (`IHomeostatSwitches.Changed`) are raised synchronously, on the thread that made the change:
  callers and tests rely on seeing the event before the call returns; handlers must be quick.
- HTTP client and call signals take one lock per client per call: the measured overhead is a fraction of a microsecond
  (see [Performance](performance.md)); striped counters were postponed.
- A cluster plan held after a rejected approval by an instance that is gone stays held until a person releases it
  (`homeostat release`, `POST /conditions/{name}/release`): releasing it automatically would need a liveness signal for
  holds, which the stores do not have.
- Probe, Kafka and memory cache thresholds stay strict (decision I4).
